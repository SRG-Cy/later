# Later Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-friendly web app where you snap/say/paste anything; open-weight Gemma extracts what you'll need to do, code computes the last sensible moment, and a Temporal workflow sleeps until then and sends one push.

**Architecture:** FastAPI app (capture page + API) and a Temporal worker, one process each, sharing a MongoDB store. The model is reached through one OpenAI-compatible client so local Ollama and DigitalOcean serverless inference are an env swap. The model returns facts; a pure resolver does all date math.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, pydantic v2, openai (client only), temporalio, pymongo (AsyncMongoClient), httpx, sentry-sdk, elevenlabs, serpapi via httpx, pytest + pytest-asyncio. Ollama locally. Render (Docker) for hosting.

**Spec:** `docs/superpowers/specs/2026-10-23-later-design.md`

## Global Constraints

- Timezone `Europe/Dublin` via `zoneinfo`; all stored datetimes are timezone-aware UTC.
- Default reminder time 09:00 local; lead times exactly as the spec table.
- The model never computes dates. Prompt says so; resolver owns arithmetic.
- Config only via env: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `LLM_VISION_MODEL`, `MONGODB_URI`, `TEMPORAL_ADDRESS` (default `localhost:7233`), `NTFY_TOPIC`, `PUBLIC_BASE_URL`, `SERPAPI_KEY`, `ELEVENLABS_API_KEY`, `SENTRY_DSN`. `.env.example` lists all; `.env` is gitignored.
- Task queue name: `later`. Workflow id: `item-{item_id}`.
- No conversation text or images sent to Sentry (`include_prompts=False`).
- MIT license.
- **Hard stop:** feature work ends Saturday 18:00 Irish time; the rest of Saturday is the post.

## Review Focus

1. Photo of a receipt with no date printed → anchor falls back to capture date, and `evidence` says so (test in Task 1).
2. Model returns invalid JSON or a date like `"next Tuesday"` → one retry, then `needs_info`, never a crash (test in Task 2).
3. Reminder that should already have fired (old warranty) → fires immediately, item marked `late` (test in Task 1).
4. Clocks change on Sunday Oct 25 2026 in Ireland → 09:00 reminders stay 09:00 local (test in Task 1).
5. User taps Done after the workflow already sent the reminder → API returns 200, no error from a completed workflow (test in Task 5).

### Task 1: Facts schema and date resolver (pure, the heart of correctness)

**Files:**
- Create: `later/models.py`, `later/resolve.py`
- Test: `tests/test_resolve.py`

**Interfaces:**
- Produces:
  - `Kind = Literal["return_window","warranty","bill","appointment","deadline","event_tickets","other"]`
  - `class Facts(BaseModel)`: `kind: Kind`, `title: str`, `action: str`, `anchor_date: date | None`, `explicit_due: datetime | date | None`, `window_days: int | None`, `window_months: int | None`, `org: str | None`, `evidence: str`, `confidence: float`

  - `class Item(BaseModel)`: `id: str`, `created_at: datetime`, `source: Literal["photo","text","voice"]`, `raw_text: str`, `facts: Facts | None`, `resolved: Resolved | None`, `status: Literal["needs_info","scheduled","reminded","done","snoozed","cancelled"]`
  - `resolve(facts: Facts, captured_at: datetime) -> Resolved | None`
  - `LEAD: dict[Kind, timedelta]` with the spec's values

- [ ] **Step 1: Write the failing tests** (`captured_at = 2026-10-23T12:00 Europe/Dublin`)

```python
def test_return_window_from_receipt():
    r = resolve(facts(kind="return_window", anchor_date=date(2026,10,20), window_days=30), CAPTURED)
    assert r.due_at == dublin(2026,11,19,23,59)
    assert r.remind_at == dublin(2026,11,16,9,0)
    assert not r.late

def test_no_anchor_uses_capture_date():
    r = resolve(facts(kind="return_window", anchor_date=None, window_days=14), CAPTURED)
    assert r.due_at == dublin(2026,11,6,23,59)

def test_month_math_clamps_to_month_end():
    r = resolve(facts(kind="appointment", anchor_date=date(2026,8,31), window_months=6), CAPTURED)
    assert r.due_at.date() == date(2027,2,28)
    assert r.remind_at == dublin(2027,2,14,9,0)

def test_event_tickets_exact_time_minus_30_min():
    r = resolve(facts(kind="event_tickets", explicit_due=dublin(2026,10,30,9,0)), CAPTURED)
    assert r.remind_at == dublin(2026,10,30,8,30)

def test_past_reminder_fires_now_and_is_late():
    r = resolve(facts(kind="warranty", anchor_date=date(2024,11,15), window_months=24), CAPTURED)
    assert r.due_at.date() == date(2026,11,15)
    assert r.remind_at == CAPTURED and r.late

def test_clock_change_keeps_nine_am_local():
    r = resolve(facts(kind="bill", explicit_due=date(2026,10,28)), CAPTURED)
    assert r.remind_at.astimezone(DUBLIN).hour == 9
    assert r.remind_at.utcoffset() == timedelta(0)   # after Oct 25 Ireland is on GMT

def test_nothing_to_resolve_returns_none():
    assert resolve(facts(kind="other"), CAPTURED) is None
```

### Task 5: Temporal reminder workflow + worker + notifier

**Files:**
- Create: `later/workflow.py`, `later/activities.py`, `later/notify.py`, `later/worker.py`
- Test: `tests/test_workflow.py`, `tests/test_notify.py`

**Interfaces:**
- Consumes: `ItemStore`, `Item` (Tasks 1, 4)
- Produces:
  - `@workflow.defn class ReminderWorkflow`: `run(item_id: str, remind_at_iso: str) -> str` returning final status; signals `done()`, `snooze(days: int)`, `cancel()`.
  - `@activity.defn async def send_reminder(item_id: str) -> None` — loads item, calls `notify`, sets status `reminded`. Retry policy: initial 2s, backoff 2.0, max 5 attempts.
  - `async def notify(item: Item, http=None) -> None` — POST `https://ntfy.sh/{NTFY_TOPIC}`, headers `Title: Later: {item.facts.title}`, body = `item.facts.action` + due date, `Actions: http, Done, {PUBLIC_BASE_URL}/items/{id}/done, method=POST; http, Snooze 3 days, {PUBLIC_BASE_URL}/items/{id}/snooze?days=3, method=POST`.
  - `async def start_reminder(client: Client, item: Item) -> None` and `async def signal(client, item_id, name: str, arg=None) -> None` (swallows "workflow already completed").
- Workflow loop: wait with `workflow.wait_condition(lambda: self._changed, timeout=remind_at - workflow.now())`; on timeout run activity, return `"reminded"`; on `snooze` move `remind_at` forward and loop; on `done`/`cancel` return that status.

  - `done` before `remind_at` → stub never called, result `"done"`.
  - `snooze(3)` after it's waiting → fires 3 days later than original, not at original time.
  - `signal(..., "done")` after completion does not raise (Review Focus 5).
  - `notify` sends exact headers above (httpx `MockTransport`).
- [ ] **Steps 2–4:** fail → implement → pass.
